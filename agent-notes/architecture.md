# Architecture reference

## Layout

The codebase is organized in a standard, logical Go folder structure:

- **`cmd/astrona/`** — CLI commands and entrypoints (`package main`):
  - `main.go` — Entrypoint: builds the root Cobra command, owns shared persistent flags (`rootFlags` struct), and registers all subcommands.
  - `config_helper.go`, `trust.go` — `LoadLabForCommand` and `requireTrust`: build `labops.LoadOptions`/`TrustOptions` from `rootFlags` (the version hand-over as `versionGate`, the terminal trust prompt `confirmTrust` as the Approver) and call `labops`.
  - `cmd_workspace.go`, `workspace_model.go` — Opt-in Kind and QEMU terminal workspace (`run --ui`, `ui [lab-name]`). Bubble Tea owns terminal input/rendering; restore the terminal before calling the shared shell, submit or destroy flows. Polling only reads isolated kubeconfigs and saved state, with bounded concurrency, output and deadlines. It must never grade, submit, renew sessions or destroy a lab. Require explicit destruction confirmation and reject actions after the saved run changes. Opening the UI is not a saved preference. `StartedAt` in lab state is local readiness time; a session's `ExpiresAt` is not a lab deadline. QEMU terminals use the student SSH identity. Resource workspaces share editable files across terminal tabs, with no host execution bridge.
  - `workspace_settings.go` — The workspace's `p` editor uses `settings.Path`, existing definitions and validation. File reads/writes run outside Bubble Tea. Saves require confirmation, share the settings lock, preserve unrelated edits and reject stale values for the selected key. Never approve new settings definitions or usage terms through this editor. Saved preferences do not reload the current command's options; cache maintenance runs only after the workspace exits. Settings remain accessible when lab actions are blocked.
  - `cmd_data.go`, `data_lock.go` — Local file usage and preview-first cleanup/reset. The entrypoint holds a shared maintenance lock during command setup and execution; confirmed maintenance takes an exclusive lock. Keep the `data` command independent of settings, lab selection and network hooks so it can repair broken local preferences.
  - `cache_policy.go` — After operational commands return, release the shared lock and try exclusive policy cleanup. Never clean during setup, a running command, or panic unwinding. Preserve the command's exit code and JSON stdout; report removed caches and deferrals on stderr. Commands exempt from settings review, including stop/destroy and logout, must not auto-clean or check releases using unreviewed preferences. Only `data clean --policy` reads preferences within the data subtree.
  - `cmd_settings.go` — The `settings` commands over `internal/settings`; explicit flags override saved values.
  - `settings_review.go`, `cmd_settings_review.go` — Review prompts over the `internal/settings` review model. Read-only `settings view` and content-based upgrade review in `settings-review.json`. The entrypoint wraps command hooks for terms and startup approval, then operational setup. Settings review is explicit and optional; never block ordinary commands on a missing or outdated review receipt. Keep help, local maintenance, background helpers, stop/destroy and logout available without review. During explicit review, new/default/description/revision changes require acknowledgement; bump a setting's review revision when its behavior changes without a text change. Network/privacy settings must require an explicit choice; future optional tracking must default off and needs its own documented controls. Settings review is not tracking consent. Explicit CI review approval binds to definitions and saved values; normal CI runs need no settings approval or pinned review ID. Review and settings edits share `settings.json.lock` with data reset, which removes both preferences and the review receipt.
  - `cmd_terms.go` — Entrypoint terms gate, wrapped around every command's persistent setup hook. Acceptance is separate from remote-code trust and `--yes`; never add a saved auto-accept setting. Keep the explicit cleanup/help exemptions narrow.
  - `banner.go` — Prints the beautiful startup ASCII banner.
  - `cmd_*.go` — One file per top-level command (`run`, `destroy`, `submit`, `ssh`, `test` (as `cmd_devtest.go`), `check`, `list`, `images`, `upgrade`).
- **`internal/`** — Modular business logic packages:
  - `apphome` — Build profile selected once at entrypoint startup from `main.Version`, before any state access or background work. Unversioned builds use `~/.astrona-dev`, Git caches beneath `cache/repos`, and `astrodev-` / `astrodev-test-` cluster names. Releases retain their original paths and prefixes. All managed paths and discovery must use this package; never hardcode a release path in operational code. Do not migrate credentials, settings or consent between profiles. Developer binaries must not self-upgrade or hand commands to release binaries. This is state isolation, not a host or server sandbox.
  - `terms` — Bundled CLI usage notice and a private, atomically replaced `~/.astrona/terms.json` receipt. Match both revision and content digest. CI requires `--accept-terms` on every operational invocation, even with a receipt; missing noninteractive consent must fail without reading stdin. Notice updates require a CLI release. Update `notice.txt` and `Revision` together after legal review; this acknowledgement does not change Apache-2.0 or provide a server audit. Native Windows setup and WSL use separate receipts.
  - `settings` — Validated user preferences in `~/.astrona/settings.json` (`Path`, `Load`, `Change`, `WithLock`, `Reset`), the review model and receipt (`ReviewDefinitions`, `Pending`, `ReviewID`) and `LoadCachePolicy`. Writes use a file lock and atomic replacement. Credentials and trust remain separate. A foundation package: it never prompts and must not import command, UI or lab packages. Compute paths inside functions, never in a package-level `var` or `init()`, so they follow `apphome.Configure`.
  - `localdata` — Read-only file inventory and allowlisted deletion plans. Cache cleanup is blocked by saved lab state, including stopped VMs. Never treat VM disks, results, credentials, resources or bundles as disposable cache. Use bounded `os.Root` operations and preserve maintenance/settings lock inodes.
    `PlanPolicy` uses the same safety boundary: default 30 days and 50 decimal GB, configured by `cache-retention-days` and `cache-max-size-gb` (0 disables only the size cap). Evict by newest filesystem modification time per entry, expiry first and oldest first for size; group image data and sidecars. These are between-command limits, not hard disk quotas. Do not relax saved-state protection just to meet a limit.
  - `config` — Lab config models and parsing (`config.go`), unverified base image downloading/caching utility (`download.go`), and directory/path guards (`path.go`).
  - `runtime` — Dispatches runtime creation and environment state (`runtime.go`).
  - `lifecycle` — The lab pipeline every command uses: `Up` (create → links → preload → addons → lab CA → DNS → bootstrap → readiness → port forwards), linked clusters (`StartLinkedClusters`, dependency order, `--parallel`), stable names and WAN, shared CA, linked-cluster teardown, `SoftReset`. Printing, prompts and flags stay in `cmd/astrona`.
  - `version` — Release versions and `astronaVersion` constraints.
  - `preflight` — Machine and lab checks behind `check`, `doctor` and `run`: external dependencies, container engine reachability and resources, inotify limits, a lab's memory estimate and host ports. Returns `preflight.Result` values and never prints; config checks (`validate`) are passed in, so this package sits below the lab and authoring code. Printing, Homebrew hints and Cobra stay in `cmd/astrona`.
  - `labops` — The application layer the commands (and later the browser workspace) call: lab memory (`RememberedSource`, `RememberLab`, `SwitchToLab`/`ReleaseLab`, `ForgetLab`), run identity (`RunID`, `GuardRun`), lab docs (`LabDocs`, `ReadLabDoc`), the lab inventory behind `astrona list` (`CollectQEMURows`, `LookupKindRows`, `UnreachableKindRows`, `EnrichKindHealth`, `LinkedClusterOwners`, returning `LabRow`s; the table and JSON rendering stay in cmd), the signed-in account (`AccountDeps` — the test seam — and `AccountForLab`), the outbox (`QueueSignal`, `SignalClock`, `StopSession`, `RunOutboxFlusher`, the body of the hidden `outbox-flush`, and `StartOutboxFlusher`, which starts it detached), result sending (`SendResult`, which writes outcomes to `w` and warnings to `warn`, never stdout), lab session start (`StartSession`, `LabSessionError`, `NotSignedInError`), timed playgrounds (`StartPlaygroundWatchdog`, `SpawnDetached`, `WatchPlayground` — the body of the hidden `playground-watchdog`, given a destroy func by cmd — `StopPlaygroundClock`, `EndRunSession`/`EndOldSession`, `StopWatchdog`, `ClampDeadline`; `RunningPlaygrounds` and `RenewPlayground`, which returns a `RenewResult` that cmd prints), the usage reporter (`StartUsageReporter`, `ReportUsage` — the body of the hidden `usage-reporter`, given a `UsageSampler` by cmd, which keeps the container/QEMU measuring), the lab loader (`LoadLab` with `LabSource` and `LoadOptions`: resolve, parse, the `astronaVersion` gate, warnings, bundle images — the hand-over itself is the `VersionGate` callback cmd passes, `ensureLabVersion`, so it still runs before any lock or side effect) and the remote-lab trust policy (`RequireTrust`, `RequireTrustUnparsed`, `HandoverApproval`, `RiskSummary`, `ResourceRefs`; asking the user goes through the `Approver` callback in `TrustOptions` — the terminal prompt in cmd, later a browser question). Detached helpers keep their argv (`astrona <command> <cluster>`, matched by `ps` in `StopWatchdog`), `Setsid` and log paths. The Cobra commands, flag reading, login/logout and the printing of results stay in `cmd/astrona`. Never prints to stdout/stderr itself (takes an `io.Writer` or returns errors), never reads flags (`--keep-resources` arrives as `ForgetOptions.KeepResources`), and never imports Cobra, Bubble Tea, `authoring` or `workspace` (depguard). `rootFlags` and the warnings stay in `cmd/astrona`. Destroy, stop and start: `DestroyByName` (takes the lab's mutation lock; `DestroyByNameLocked` for a caller already holding it, e.g. the workspace's delete), `DestroyByPattern`, `DestroyByDiscovery`, `DestroyLab` (a loaded `Teardown`, under the lock, run-identity checked) and `TearDownLabEnvironment`; outcome lines go to `DestroyOptions.Out`, forget warnings to `DestroyOptions.ForgetWarn`, and `--keep-resources` arrives in `DestroyOptions.Forget`. An unreachable container engine is never "lab absent" (`EngineUnreachable`), port forwards are always stopped, and the exam clock is cleared only once the lab is confirmed gone. `ResolveKindLab`, `PlanStop`/`Stop` and `Start` (returns a `StartResult` cmd prints) back `astrona stop`/`start`, which take no lab lock. The teardown trust prompt (`teardownTrusted`), the catalog-name argument and the `destroy`/`stop`/`start` output stay in cmd.

    Run and reset: `Provision` takes a `ProvisionRequest` (config, base dir, remembered `Source`, `LocalOnly`, `KeepContext`, `Parallel`, the lab `Session`, the preflight `ConfigChecks`, a `Warn` writer) and does what `bringUpLab` did — environment preflight, resources snapshot, linked clusters, `lifecycle.Up`, diagnostics on failure, the exam clock, `RememberLab`, closing the reporter and the kubectl switch — returning a `ProvisionResult` (env, forwards, links, `Switched`, resources, log path) that cmd's `bringUpLab` prints. Also here: `LabExists`, `OtherRunningLabs`/`OtherRunningLabNames`/`OtherQEMULabs`, `RemoveForRestart` (the start-over teardown, `releaseLab` first with `--keep-context`), `StartLabSession` returning a `LabStart` (`Progress`, `Abandon`, `Done` — the usage reporter and playground watchdog start in `Done`, as before), `SoftReset`, `PlanLinkedReset`/`ResetLinkedCluster` (planned before the confirmation, built after) and `WriteTimeLimit`. The run lock (`labstate.LockMutation`), every prompt (`chooseRun`, `confirmReset`, the guest and UI-restart questions), the UI offer and terminal-UI wiring (`discardUIRun`, `runLabWorkspace`), Cobra and all printing stay in cmd; the version hand-over still runs in `LoadLab` before the lock. The diagnostics collectors (`CollectDiagnostics`, `CollectLinkedDiagnostics`, `Diagnose`, `QEMUConsoleLogs`, `WriteDiagnosticsSummary`, `WriteLinkedDiagnostics`) live in labops, not `internal/diagnostics`: they need `lifecycle.OwnedClusters`, and `internal/diagnostics` stays a leaf collector for one environment that lifecycle could call without a cycle. `astrona diagnose` resolves the lab in cmd and calls `Diagnose`; `--diagnostics` mode validation stays with `astrona test` in cmd.
    Status and terminals (S11): `Status` gathers a running lab's `LabStatus` and returns the `StatusResult` that `status -o json` prints (`Lab` holds the facts the text view renders, `json:"-"`), with `ResolveStatusLab`, `FindLabRow`, `NextStep` and `ForwardsJSON`; `ResolveKindCluster` (given a `LoadLabFunc` by cmd), `LabKubeconfig`, `ShellKubeconfigs` and `ShellCommand` build the isolated kind terminal through `IsolatedLabCommand` (labshell, the test seam; cmd passes whether stdin is a terminal); `PrepareSSH` builds `astrona ssh` (isolated `sshopts`, the lab's known_hosts, `VMWorkspaceShell`; the VM resource workspace is the `PrepareWorkspace` callback from cmd) and `SSHSession.Command` adds the deprecated `--password` askpass environment (`AskpassEnvVar`). cmd keeps the Cobra commands, the nested-shell and `--ask-password` terminal checks, the text rendering of status, the pane title and messages, and running the command attached (`runAttached`, signal handling).
    Submit (S13): `Submit(ctx, SubmitRequest)` returns a `SubmitResult` (`Passed` false is a failed grade, never an error, so exit code 2 stays in cmd). `PrepareSubmit` holds the checks before grading (config validation, `GuardRun`, `RequireTrust`, `RequireRunningKindLab`, the environment, the "submit" reporter and the Proctor) and is where `submit --watch` starts. Submit calls `proctor.Evaluate` and renders the text report with `Proctor.Report` on `SubmitRequest.Out` (nil under `-o json`; script output then goes to `ScriptOut`); the `Graded` hook is where cmd writes the JUnit report and prints the result (text or JSON), before `SendResult` gets the result capped by `CapCheckTexts`. `Submission`/`SubmissionCheck` are the `-o json` shape (`NewSubmission`); `FindSavedRun`, `PickRunningLab`, `RunningLabNames`, `LabOfVM`, `SubmitHistory` and `StrictOverTime` live here too. Submit takes no lab lock. cmd keeps the Cobra command, flag checks, picking the lab from flags, printing, the FAIL line and the exit code.
  - `labshell` — Student Kind terminals run in a tools container. Only the per-run `runtime/<lab>/work` directory is writable from the terminal; never mount host homes, engine sockets or SSH agents. Keep failure closed: no host shell fallback. UI image preparation must be cancellable without holding the rendering lock. QEMU terminals remain inside their VM with SSH local escapes disabled.
  - `cluster` — Handles container engine detection and Kind cluster lifecycle (`cluster.go`).
  - `hypervisor` — Manages QEMU VM background processes, UEFI vars, and multi-NIC topology (`hypervisor.go`).
  - `executor` — Defines shell execution abstractions on the host or over SSH (`executor.go`).
  - `scripts` — Sequentially executes init, bootstrap, and testing scripts (`scripts.go`).
  - `manifests` — Applies Kubernetes manifests to clusters (`manifests.go`).
  - `proctor` — The central grading authority that runs validation checks (`proctor.go`). `Evaluate` grades without printing, `Report` renders the human report to a writer, and `Grade` is `Evaluate` + `Report` on stdout (used by `astrona test`).
  - `junit` — Formats and writes test report XML files (`junit.go`).
  - `authoring` — Lab-author workflows without Cobra: `Scaffold`/`ScaffoldLinked` render the `astrona init lab` starters from the embedded `templates/` tree (`init.go`); `astrona content` (`content.go`) resolves a local or git source (`ResolveContentSource`), validates ATS trainings (`ValidateATS`) and ATP paths (`ValidateATP`), builds an ATP bundle (`BuildATP`) and scaffolds from a blueprint repository (`InitContent`, with optional CODEOWNERS and GitHub repository setup), writing progress to the `io.Writer` it is given. The commands, flags and printing stay in `cmd/astrona`; depguard keeps Cobra and the workspace out of it.
  - `gitsource` — Clones and caches external lab config repositories (`gitsource.go`).
  - `labstate` — What astrona remembers per running lab in `~/.astrona/labs/<lab>.json` (0600): its config source (so `submit` can find the only running lab), the kubectl context `run` switched away from (restored by `destroy`), and its Astrona lab session (never a token).

## Suggested reading order (new to Go / new to this repo)

1. `cmd/astrona/main.go` — entry point: shows how Cobra wires commands together.
2. `internal/executor/executor.go` — one interface (`ScriptExecutor`), two implementations. The clearest example in this repo of *why* Go interfaces exist.
3. `internal/runtime/runtime.go` — dispatches on `runtime.type`, returns the same `LabEnvironment` shape regardless of backend.
4. `internal/config/config.go` — the YAML shape every command loads.
5. `cmd/astrona/cmd_run.go` — shortest, most linear command.
6. `internal/scripts/scripts.go` / `internal/manifests/manifests.go` — what actually runs during bootstrap.
7. `internal/proctor/proctor.go` — the grading seam every "did the lab pass" decision goes through.
8. `internal/hypervisor/hypervisor.go` last — the most involved file, but broken into small, individually-named steps.
